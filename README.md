# 테니스 타점 복원 데모 페이지

과학기술글쓰기 연구포스터 「스마트 고글을 활용한 테니스 타점 측정 및 실시간 피드백 시스템」의 '데모' QR이 가리키는 페이지다(https://leehw78.github.io/tennis-goggle-demo/). 포스터의 핵심 설계인 '프레임 사이 타점 복원'을 공개 고속 영상으로 사전 검증한 결과를 싣는다. 빌드 도구 없이 이 폴더를 그대로 GitHub Pages에 올린다.

## 구성

- `index.html`: 페이지 본문. 문구만 있고 숫자는 `data.js`에서 채운다.
- `static/css/site.css`: 색 토큰(밝은·어두운 화면)과 배치.
- `static/js/data.js`: 페이지의 모든 숫자와 자료 목록. 평가 결과에서 스크립트로 만든 파일이라 직접 고치지 않는다.
- `static/js/app.js`: 숫자 채우기, 대표 영상 재생 단추, 넘겨 보기(canvas), 임팩트 위치별 오차 그림(SVG), 타구별 표와 그림, 영상 출처. 외부 스크립트를 쓰지 않는다.
- `static/media/`: 대표 영상 `hero.mp4`와 `hero_poster.jpg`, 타구별 그림 `strokes/<id>.jpg`, 넘겨 보기 프레임 `scrub/<id>/f###.jpg`.

평가 파이프라인과 그림·자료를 만드는 스크립트는 이 저장소에 들어 있지 않다.

## 무엇을 검증했나

- 자료: 공개 고속 영상 6편(240–1000 fps)의 타구 12개.
- 방법: 고속 영상에서 30 fps 프레임만 사용하고, 프레임 추출 위치를 바꿔 가며 타구당 8–33회 반복. 공 검출은 WASB-SBDT(Tarashima et al., BMVC 2023)의 공개 모델을 추가 학습 없이 사용. 타점 복원은 물리 시뮬레이션 타구로 학습한 소형 Transformer.
- 실제 타점: 고속 원본의 모든 프레임에서 공 궤적을 추적해 구한, 공이 줄에 처음 닿는 순간의 공 중심.
- 오차: 추정 타점과 실제 타점 사이의 거리(화면 평면 기준, 공 지름 6.7 cm로 환산).

## 싣는 규칙

- 대표 숫자는 타구가 단위다. 타구마다 반복의 중앙값을 그 타구의 오차로 삼고, 타구 12개의 중앙값을 낸다.
- 'AI 복원'은 30 fps 영상만 쓴 추정, '임팩트 시각을 알면'은 고속 원본의 임팩트 시각에 0.5 ms 오차를 넣어 알려 준 경우, '복원 없음'은 임팩트에 가장 가까운 30 fps 프레임의 공 위치다.
- 공 검출에 실패한 타구도 통계에서 빼지 않는다.
- 유소년 선수의 영상(타구 11·12)은 수치와 영상 출처에만 넣고 장면은 싣지 않는다.
- 라임색은 AI가 검출하고 추정한 것, 흰 고리는 실제 타점에만 쓴다.

## 영상의 이용

YouTube 공개 영상을 교육·연구 목적으로 출처를 밝혀 일부 인용했다(저작권법 제28조). 권리자가 원하지 않으면 해당 영상을 내린다.
